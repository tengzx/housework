时间日历接口需求文档

用于记录页日历视图。第一版先支持按日期范围展示、修改分类、修改起止时间；后续支持补录、删除和进行中记录。

一、通用约定

时间格式：所有时间字段使用 ISO 8601，并带时区，例如 2026-06-22T09:00:00+03:00。

日期范围：from 和 to 使用 YYYY-MM-DD。建议 to 按包含当天处理。

颜色：分类颜色由后端返回十六进制色值，例如 #7B8AF0。

重叠记录：当前 UI 可以显示重叠，但建议后端返回冲突提示或统一决定是否允许重叠。

二、最小交付接口

第一版日历接入后端，至少需要以下 3 个接口：

  • GET /api/time-events?from=&to=：拉取日历记录
  • GET /api/time-categories：拉取分类和颜色
  • PATCH /api/time-events/{id}：修改记录分类、名称、起止时间

三、接口详情

GET /api/time-events?from=2026-06-21&to=2026-06-25

按日期范围获取日历记录。日历左右滑动时会按可见日期范围分页拉取。

返回示例

{
  "events": [
    {
      "id": "evt_001",
      "name": "睡觉",
      "categoryId": "rest",
      "typeId": "sleep",
      "startedAt": "2026-06-21T05:30:00+03:00",
      "endedAt": "2026-06-21T08:00:00+03:00",
      "source": "shortcut",
      "note": ""
    }
  ]
}
字段类型说明
idstring记录唯一 ID
namestring显示在日历色块上的名称
categoryIdstring大类 ID，用于决定颜色
typeIdstring小类 ID
startedAtstring开始时间，ISO 8601，带时区
endedAtstring | null结束时间；进行中记录可为 null
sourcestring来源，例如 shortcut、manual、import
notestring备注，可为空

GET /api/time-categories

获取大类、小类和大类颜色。详情弹窗的分类选择器依赖这个接口。

返回示例

{
  "categories": [
    {
      "id": "work",
      "label": "工作",
      "color": "#7B8AF0",
      "types": [
        { "id": "work_office", "label": "上班" },
        { "id": "coding", "label": "写代码" },
        { "id": "meeting", "label": "开会" }
      ]
    },
    {
      "id": "life",
      "label": "生活",
      "color": "#3FA9F5",
      "types": [
        { "id": "breakfast", "label": "吃早饭" },
        { "id": "lunch", "label": "吃午饭" }
      ]
    }
  ]
}

PATCH /api/time-events/{id}

修改单条记录。用于详情弹窗里修改分类、小类、名称、起止时间和备注。

请求示例

{
  "categoryId": "work",
  "typeId": "coding",
  "name": "写代码",
  "startedAt": "2026-06-22T09:00:00+03:00",
  "endedAt": "2026-06-22T11:00:00+03:00",
  "note": ""
}

返回示例

{
  "event": {
    "id": "evt_001",
    "name": "写代码",
    "categoryId": "work",
    "typeId": "coding",
    "startedAt": "2026-06-22T09:00:00+03:00",
    "endedAt": "2026-06-22T11:00:00+03:00",
    "source": "manual",
    "note": ""
  }
}

后端校验建议：

  • endedAt 必须大于 startedAt
  • 最小持续时间建议为 1 分钟或 5 分钟
  • 如果不允许重叠记录，返回明确错误码和冲突记录 ID

四、后续增强接口

POST /api/time-events

新增或补录记录。后续如果支持在日历中长按/拖拽创建事件，需要该接口。

请求示例

{
  "name": "跑步",
  "categoryId": "health",
  "typeId": "running",
  "startedAt": "2026-06-22T13:30:00+03:00",
  "endedAt": "2026-06-22T14:20:00+03:00",
  "note": ""
}

DELETE /api/time-events/{id}

删除记录。后续详情弹窗增加删除按钮时使用。

返回示例

{
  "ok": true
}

GET /api/time-events/running

获取当前正在进行中的记录，用于和记录页同步，也可以在日历中显示持续中的色块。

返回示例

{
  "event": {
    "id": "evt_running",
    "name": "写代码",
    "categoryId": "work",
    "typeId": "coding",
    "startedAt": "2026-06-25T09:20:00+03:00",
    "endedAt": null,
    "source": "shortcut",
    "note": ""
  }
}

没有进行中记录时：

{
  "event": null
}

五、错误返回建议

{
  "error": {
    "code": "TIME_EVENT_CONFLICT",
    "message": "该时间段与已有记录重叠",
    "details": {
      "conflictEventId": "evt_099"
    }
  }
}
